System Failure Safety Fail-Closed By Design

SettleGraph's optional AI reasoner (engine/ai_reasoner.py) only ever proposes a hypothesis for an exception the deterministic matcher already could not resolve. The model never decides a match: its hypothesis is fed back through the same deterministic invariant gate (verify_settlegraph_invariants) every AUTO_MATCH must clear, and only promotes to AI_RESOLVED_MATCH — never AUTO_MATCH — if every invariant passes.

Every failure path leaves the record exactly where the deterministic layer put it. A timeout, a rate limit, a connection error, a refusal, malformed JSON, an out-of-range confidence, a candidate id the model was never shown, or a hypothesis that fails an invariant — all of these mean the record stays EXCEPTION, now carrying the model's rationale as extra context for whoever reads the queue next. Invalid output is discarded, not guessed around.

This behavior is enforced in code, not asserted in the UI — it is exercised directly by the Failure Sandbox tab.
